## ما كان موجودًا

- تطبيق أولي صغير يعتمد على استدعاءات Anthropic متسلسلة.
- قاعدة SQLite بسيطة تربط النتائج باستخدام `obligation_id` فقط، ما كان يسمح بتضاعف النتائج بين التشغيلات.
- وحدات منفصلة لاستخراج الالتزامات، وفحص الانطباق، وتحليل الفجوات، وإنشاء المهام.
- ملفا بيانات تجريبية كانا يحتويان عبارات تكشف الإجابة مثل `EXCEEDS LIMIT` و`within limit`.
- لم تكن توجد اختبارات، أو API متكاملة، أو واجهة مراجعة بشرية، أو إصدارات وثائق غير قابلة للاستبدال، أو كشف تغييرات، أو استئناف دائم لحالة الوكيل.
- التشغيل الأصلي توقف بسبب غياب حزمة `anthropic`.

## ما تم إصلاحه وبناؤه

- تحميل آمن لمتغيرات البيئة، ومسارات ثابتة انطلاقًا من جذر المشروع، وملف `.env.example` بلا أسرار.
- تهيئة قاعدة البيانات تلقائيًا وتطبيق migrations مع الحفاظ على الجداول القديمة باسم `legacy_*` عند وجودها.
- نموذج بيانات مترابط لـ Source وDocumentVersion وClause وRegulatoryChange وObligation وCompanySnapshot وEvidence وApplicabilityResult وFinding وTaskDraft وReview وAuditEvent وRunState.
- إضافة `run_id` و`finding_id` وعلاقات ومفاتيح فريدة ومعرّفات عدم تكرار لمنع تكرار النتائج والمهام.
- تخزين إصدارات الوثائق ببصمة SHA-256، مع منع استبدال النسخ السابقة وربط المقاطع بالمصدر والموضع.
- كشف حتمي للإضافة والحذف والتغيير الرقمي أو الزمني أو النطاقي والتغيير التحريري.
- قواعد برمجية للمقارنات الرقمية والوحدات والتواريخ بدل تفويضها للنموذج اللغوي.
- فصل النصوص التنظيمية عن أدلة المنشأة، واسترجاع المقاطع والأدلة الفعلية وربط كل استنتاج بمراجعه.
- حالات `unknown` و`insufficient_evidence` و`conflicting_evidence`، ومنع إنشاء مهمة علاجية دون دليل كافٍ على الفجوة.
- وكيل بحالة صريحة ودائمة، و`thread_id`، ونقاط تحقق، واستئناف بعد الانقطاع، ومحاولتي استرجاع كحد أقصى، وتوقف عند نقص الأدلة أو تعارضها.
- واجهة `LLMClient` موحدة وقابلة للاستبدال مع تحقق Pydantic، ومعالجة JSON، ومهلات، وإعادة محاولة محدودة. لم تُستخدم سلسلة التفكير الداخلية ولم تُحفظ.
- نقطة توقف بشرية، مع قبول أو تعديل أو رفض المهمة، والتحقق من الدور و`expected_revision`، وحفظ المراجع والوقت والإصدار في سجل التدقيق.
- FastAPI مع جميع المسارات المطلوبة، تشغيل غير متزامن برمز `202`، CORS مقيد، وصلاحيات محلية أساسية للأدوار.
- واجهة عربية RTL متجاوبة تعرض المصدر والنسخ والفرق ومراحل الوكيل والنتائج والأدلة والمهام والمراجعات وسجل التدقيق والتقرير.
- بيانات عرض منفصلة ونظيفة، تشمل حالات إيجابية وسلبية ونقص دليل وتعارض، مع وسم واضح بأن الإصدار المعدل **محاكاة تغيير وليست تحديثًا رسميًا**.
- README شامل، وخطة P0/P1/P2، وسيناريو عرض وقرارات هندسية وخارطة توسع.

## أفضل سيناريو عرض أمام لجنة التحكيم

1. افتح الصفحة ووضّح أن المصدر التجريبي والإصدار المعدل موسومان كمحاكاة وغير معروضين كتنظيم رسمي.
2. اعرض النسختين وبصمتي SHA-256 ثم الفرق بين النص قبل التغيير وبعده.
3. اضغط تشغيل التحليل وتابع انتقال الوكيل بين المراحل حتى `awaiting_review`.
4. اعرض التغيير الرقمي الجوهري، ثم الالتزامات والنتائج المنطبقة وغير المنطبقة.
5. افتح حالات نقص الدليل والتعارض، واشرح لماذا توقف النظام ولم ينشئ مهمة علاجية لها.
6. اعرض الفجوة المدعومة بالدليل، والأصل المتأثر، والأولوية، ومؤشرات جودة المصدر وحداثة الدليل وصحة الاستشهاد وكفاية شروط الانطباق.
7. اعرض المهمة المسودة المرتبطة بالمادة والدليل، ثم عدّلها أو اعتمدها كمراجع.
8. اعرض انتقال التشغيل إلى `completed` وسجل التدقيق، ثم أعد التشغيل بنفس مفتاح عدم التكرار لإثبات عدم تكرار المهمة.
9. اختم بالتقرير النهائي وحدود النموذج الأولي وخطة الانتقال إلى PostgreSQL وعامل مهام مستقل وهوية مؤسسية.

## القيود والمطلوب من المستخدم لاحقًا

- يلزم `ANTHROPIC_API_KEY` لاختبار المسار الحي للنموذج. النظام يعمل في العرض الحتمي بدونه.
- الحدود والنصوص في سيناريو العرض اصطناعية وليست فتوى أو تحديثًا تنظيميًا رسميًا.
- الصلاحيات الحالية مناسبة لعرض محلي وتعتمد رؤوس API/رمزًا اختياريًا؛ الإنتاج يحتاج OIDC/SSO وإدارة هوية مركزية.
- المهام الخلفية تعمل داخل عملية FastAPI؛ الإنتاج يحتاج عامل مهام مستقلًا مثل Celery أو Dramatiq مع broker.
- SQLite مناسبة للعرض؛ الانتقال الإنتاجي المستهدف هو PostgreSQL مع migrations مُدارة.
- البحث النصي ومعرّفات المواد كافيان للـMVP الحالي؛ البحث الدلالي مؤجل حتى تظهر حاجة مقاسة.
- معاينة DOCX بصريًا لم تُنفذ لأن بيئة الأدوات لم تتضمن LibreOffice، لكن محتواه قُرئ كاملًا. ملفات PDF استُخرج نصها وعُرضت صفحاتها بصريًا.
- تحذيرا الاختبارات مرتبطان بإصدارات تبعيات الاختبار ويمكن إزالتهما مستقبلًا بتحديث متوافق.
